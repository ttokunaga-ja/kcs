# Orchid Ledger ドキュメント整備メモ

**July 2026 · Ledger Platform**



## 読み直した範囲

Hummingbird Payments の integration guide を読み、導入手順と業務用語のずれを解消した。利用者が最初に触れる資料では、内部コンポーネントの名称よりも「依頼を送る」「結果を受け取る」という順序を優先する。



## 反映した方針

- 依頼の識別子は作成側が保持し、問い合わせ時にも同じ値を使う
- webhook の例は署名確認の前後が分かる流れにする
- `posted_at` は画面表示用の時刻ではなく業務上の記帳日として説明する
- 結果イベントの用語は release note と API reference で統一する



## 残したコメント

パラメータ一覧だけを読んだ利用者でも、どの段階で失敗を直せばよいか判断できるかを次のレビューで確認する。設計資料へのリンクは補助情報に留め、導入手順の途中に割り込ませない。

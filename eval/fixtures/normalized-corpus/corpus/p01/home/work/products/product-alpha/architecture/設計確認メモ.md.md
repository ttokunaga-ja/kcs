# Orchid Ledger の設計確認メモ

**July 2026 · Ledger Platform**



## 今日整理したこと

Hummingbird Payments の勘定更新を扱う Orchid Ledger について、入口から記帳までの責務を言葉でそろえた。外部から受け取る依頼はまず `posting intent` として正規化し、ドメイン層では利用者向けの文言を持ち込まない方針にする。

- edge adapter は入力の整形と認証済みの呼び出し元の受け渡しだけを担う
- ledger writer は検証済みの命令だけを受け、結果をイベントとして残す
- read projection は利用者向けの表示を組み立てる。記帳規則をここへ置かない



## 合意した境界

依頼を識別するキーは入口で受け取り、記帳命令と一緒に保持する。再送時の扱いを各呼び出し元に委ねると差分が出やすいため、同じ入口で一貫して判定する。

また、失敗理由は外部 API 用の文面と内部の診断情報を分離する。運用者が調査するときは内部の理由を追え、クライアントには安定したエラー分類だけが返る状態を目指す。



## 次に確認すること

- 監査画面がイベントの因果関係を追えること
- API 契約の例が今回の用語にそろっていること
- release note の変更説明が実装の境界を越えていないこと

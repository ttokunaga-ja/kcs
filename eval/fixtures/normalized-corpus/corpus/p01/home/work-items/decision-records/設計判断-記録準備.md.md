# 設計判断の記録準備

**July 2026 · Orchid Ledger 2026.07**



## 判断対象

Ledger Platform では、外部 API の依頼をそのまま記帳処理へ渡さず、`posting intent` を経由させる設計を採用する。入力の都合と記帳規則を別々に進化させられることが理由である。



## 比較した案

| 案 | 利点 | 懸念 |
| --- | --- | --- |
| API の項目を直接使う | 実装が短い | 外部仕様が内部規則に残る |
| 専用の命令へ変換する | 境界が明確 | 変換の説明が必要 |
| 画面側で意味を補う | 表示は柔軟 | 記帳規則が分散する |



## 記録に残すこと

採用理由、対象外にした案、移行時に確認する利用者向けの文言を一つの ADR にまとめる。Poppy Gateway はこの判断の利用者ではなく、結果イベントを受け取る別の境界として扱う。

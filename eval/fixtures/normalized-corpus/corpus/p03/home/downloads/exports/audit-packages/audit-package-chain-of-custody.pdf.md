## 監査パッケージのチェーン・オブ・カストディ

証跡を受領してから提出参照を固定するまで

運用主体　Trust Engineering / GRC　|　対象: Q3 2026 SOC 2 readiness

監査パッケージは原本の保管場所を置き換えない。誰が、いつ、どの版を確認したかを追える状態にするための管理記録である。



### 受領時

資料提供チームは、対象システム、対象期間、担当窓口を添えて送付する。Evidence Coordinator は、資料そのものではなく、受付番号と保管場所を一覧に残す。



### 提出参照の固定

提出参照を固定した後も、原本は通常の運用に従って更新される。新しい版が出た場合は、提出済みの参照を変更する前に、監査パッケージの担当者が差分と影響を確認する。



### 確認時

- 統制との関連が分かる説明を確認する。
- 抽出条件や対象期間が不足していないか確認する。
- 制限付きの原本には、必要な最小人数だけがアクセスできることを確認する。
- 差戻しになった場合は、理由と再提出の見込みを受付表に残す。

|  引継ぎ情報 | 確認する内容  |
| --- | --- |
|  保管参照 | 原本へ到達できる安定した参照か  |
|  版情報 | 更新前後が区別できるか  |
|  確認責任者 | 内容確認をした担当が分かるか  |
|  制約事項 | 共有範囲や閲覧条件が明確か  |

### 再確認が必要になる例

|  事象 | 対応  |
| --- | --- |
|  対象期間の訂正 | 影響する提出候補を再確認する  |
|  資料の版更新 | 新旧の差分と理由を記録する  |
|  統制説明の変更 | Control Owner と対応関係を見直す  |
|  閲覧条件の変更 | 参照先のアクセスを再確認する  |

監査パッケージの履歴は、事実関係を追うためのもの。原本の削除や保持判断は各システムの正式な運用に従う。

### 基本原則

原本は提供チームまたは承認済みの保管領域に残し、監査パッケージには参照と要約を置く。受領後に資料が更新された場合は、古い参照を上書きせず、後継版との関係を記録する。

|  状態 | 意味 | 記録する事項  |
| --- | --- | --- |
|  受領 | 提供元から資料を受け取った | 日時、提供者、資料種別  |
|  確認中 | 範囲・期間・機微性を確認している | 確認者、懸念点  |
|  提出候補 | 統制との対応づけが済んだ | Control Owner、参照先  |
|  固定 | 提出時点の参照を確定した | 固定日、版、提出担当  |



### 対象外

チャットの下書きや個人作業メモは、正式な受領記録の代わりには使わない。必要な判断が会議で行われた場合は、決定事項を記録に転記してからパッケージへ反映する。

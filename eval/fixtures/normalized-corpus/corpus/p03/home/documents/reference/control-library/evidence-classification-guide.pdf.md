## 証券分類ガイド



### SOC 2 readiness 用 - Trust Engineering 運用基準

適用範囲　東京運用環境の監査証券　|　版: 2026 年 7 月 運用版

監査資料を集める前に、内容の機微度と提出方法をそろえるための実務ガイド。分類は保管場所ではなく、資料に含まれる情報で判断する。



### 1. 受領時の記録

受領した資料には、提供元、対象期間、版、確認予定者を受付表に残す。ファイル名だけで内容を判断せず、先頭ページまたはヘッダーで対象システムと期間を確認する。



### 担当者の役割

|  役割 | 責任  |
| --- | --- |
|  資料提供チーム | 原本の正確性、対象期間、更新予定の説明  |
|  Evidence Coordinator | 提出候補の粒度と受領状況の管理  |
|  Trust Engineering | 統制との対応関係と機微性の助言  |
|  Control Owner | 提出可否と例外の最終判断  |



### 2. 内容確認

|  確認観点 | 実務上の判断  |
| --- | --- |
|  対象範囲 | 東京運用環境または共通統制に紐づくか  |
|  完全性 | 期間の開始・終了、承認者、抽出条件が分かるか  |
|  機微性 | 個人情報、資格情報、詳細な運用ログを含むか  |
|  鮮度 | 対象期間に対して適切な版か  |



### 分類の考え方

証券は「提出用要約」「内部運用記録」「制限付き原本」の三段階に分ける。提出用要約は監査パッケージで参照できる形に整え、内部運用記録は担当チームが保持する。制限付き原本は最小限の確認者だけが取り扱う。

|  区分 | 主な例 | 取り扱い  |
| --- | --- | --- |
|  提出用要約 | 管理者レビューの集計、承認一覧 | 監査パッケージへ参照追加  |
|  内部運用記録 | 変更チケット、当番メモ | チーム領域で保管  |
|  制限付き原本 | セッション詳細、個人情報を含む添付 | 限定権限で保管  |



### よくある取り違え

レビューの集計値だけでは、抽出条件が不明な場合がある。逆に、詳細ログをそのまま提出すると、必要以上の情報を渡すことになる。目的に必要な説明を要約に集め、原本は参照可能な状態で保つ。



### 3. 提出候補の作成

提出用要約には、資料の由来、対象期間、確認者、原本への参照だけを記す。制限付き原本を添付する必要がある場合は、提出経路と閲覧者を事前に合意する。

分類が変わるときは、古い区分を消さず、判断理由と変更日を受付表に追記する。

### 更新の目安

制度変更、組織変更、利用ツールの切替があったときは、分類例と提出経路を見直す。月次の readiness 同期で、各チームから分類上の迷いを集める。

このガイドは統制設計書の代替ではない。統制の要求内容は各 Control Owner の記録を正とする。

Internal working reference | 3

### 迷ったときの確認順

- 顧客や従業員を直接識別できる情報が含まれるか確認する。
- 原本の代わりに期間・担当・結論を示す要約で足りるか判断する。
- 提出先が求める粒度を Evidence Coordinator と照合する。

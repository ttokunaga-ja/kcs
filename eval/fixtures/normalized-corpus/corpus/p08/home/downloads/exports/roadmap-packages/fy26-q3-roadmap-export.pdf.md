# テーマ別の確認面

担当の会話を揃えるための要約

|  テーマ | 意図 | Q3 の確認材料  |
| --- | --- | --- |
|  **Intent capture** | 利用者が調べ始める理由を、短い文脈と共に残す。 | セッション記録、保存した検索、アカウント担当の振り返り。  |
|  **Review surface** | 候補を比べ、参照元を確かめる場をつくる。 | プロトタイプ反応、参照情報の分かりやすさ、比較時の迷い。  |

|  **Platform readiness** | 体験に必要な依存先の状態を見えるようにする。 | 更新の安定性、参照情報、運用上の確認手順。  |



# リスクと見直しの観点

ポートフォリオを固定せず、観察に合わせて調整する



# この書き出しについて

これは Q3 のポートフォリオ確認で使う作業用の一覧です。日々のプロダクト判断を置き換えるものではなく、各テーマの意図、依存先、学習の手がかりを同じ画面で確認できるようにまとめています。



# 確認が必要な依存関係

|  参照情報の新しさ | 利用者に見える更新の手がかりと、内部の更新処理の状態が食い違わないこと。  |
| --- | --- |
|  アカウント文脈の扱い | 個別の会話に必要な範囲だけを保ち、別の担当でも意図を読み取れること。  |
|  レビュー記録の持続性 | 一度の検討で終わらず、後から戻った人が根拠と判断をたどれること。  |



# ポートフォリオの焦点

Harbor discovery の検証、利用者が根拠を確認できるレビュー面、チーム間で引き継げる共有メモ。



# Q3 の扱い

学習の境界を明確にし、platform 依存の不確実性を早めに表面化させる。



# REVIEW CADENCE

**週次:** 実験で見えた行動と platform 側の変化を短く確認する。 **隔週:** 調査記録から、継続する迷いと改善した場面を見直す。 **月次:** ポートフォリオ全体で、価値の説明と依存関係の説明が揃っているかを読む。

**Export note:** この一覧は、会話を始めるための共通の地図です。優先順位の最終判断は、研究の観察、顧客の状況、platform の確認結果を合わせて行います。

Beacon beta の準備は、Q3 の観察から得た判断基準を使って段階的に組み立てる。



# PORTFOLIO VIEW

# 進め方の原則

- 各テーマは、利用者の判断に変化があったかで振り返る。
- 学習の記録は shared workspace に残し、別チームでも追えるようにする。
- 依存先の不確実性は、解決を待たずに説明可能な形で共有する。

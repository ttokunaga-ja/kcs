# 今回の主題

Harbor の discovery は、検索結果を増やす取り組みではなく、複数の担当者が同じ判断材料に到達しやすくするための作業面として検討しています。今回の読み合わせでは、研究から得た示唆を Q3 のプロトタイプ範囲に接続しました。



# COUNCIL SUMMARY

議論は、説明可能な根拠、レビュー時の比較しやすさ、引き継ぎ時の文脈保持の三点に集約されました。広い業務フローを一度に変えるより、判断の手前にある迷いを減らすことを優先します。



# 参加した機能

|  **Product** | 学習テーマの優先順位と、次のプロトタイプの境界を整理。  |
| --- | --- |
|  **Search Platform** | 参照元、更新時刻、関連性の扱いを確認。  |
|  **Research Operations** | インタビュー記録との照合方法を共有。  |
|  **Customer Enablement** | アカウント担当が説明に使える表現を提案。  |



# COUNCIL CLOSE

次の会合までの前提: Harbor は、答えを決める製品ではなく、担当者が判断材料を持ち寄って前に進むための発見環境として評価します。新しい画面の数より、根拠を持って話せる場面が増えるかを見ます。

記録は shared workspace に残し、各機能のコメントは次回のデザインレビューで再確認します。未解決事項は platform 依存の一覧と研究セッションのメモに紐づけます。

# 見送った案

一括の自動提案はまだ広すぎる。価値の説明に必要な材料が定まる前に、推奨の強さだけを上げるとレビューが難しくなるため、今回の学習対象には含めません。



# OPEN QUESTIONS

- 根拠をどこまで見せると、担当者の作業を邪魔せずに納得感をつくれるか。
- 同じアカウントで複数人が作業するとき、共有メモの粒度をどうそろえるか。
- platform の更新情報を、利用者向けの言葉へどう翻訳するか。

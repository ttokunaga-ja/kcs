# 画像を含む検索空間の設計 — レーンごとの到達範囲と、reranker の棄権

**状態: 設計。実装前。** [2026-08-11]

きっかけは `tasks/rerank-differential-plan.md` §2.9.2 の実測で、
**3 モデルとも唯一 qb22 を悪化させた** (正解 7 位 → 37〜38 位)。
正解は `citation-network.jpeg` — **画像**で、答えは画素の中にある。
テキストだけ読む cross-encoder には手がかりが無い。

---

# 1. 3 つのクラスと、各レーンの到達範囲

| クラス | 中身 | FTS | vector | rerank |
|---|---|---|---|---|
| **A** | born-digital のテキスト | ✓ | ✓ | ✓ |
| **B** | **OCR が文字に起こしたもの** | ✓ | ✓ | ✓ |
| **C** | **OCR が「画像として扱うべき」と判断したもの** | ✗ | ✓ | **棄権** |

B と C の線引きは **OCR 側の判断**である。文字に起こせたものは本物のテキストなので
全文検索に入れる。図表・写真のように起こしても意味を成さないものは、
**ベクトルでだけ引ける**ようにする。

**vector の列が 3 クラスとも ✓ なのは、既にそうなっているからである。**
07 §5.3 の埋め込みは**単一マルチモーダル空間**で、画像オブジェクトも
同じ空間に入る (`local_embedding` の `IMAGE_OBJECT_CAPABILITY`)。
別空間を作る必要はない — **作ってはいけない。**03 §7 の互換ゲートは
`tool_profile_hash` しか見ないので、同じ profile で 2 つの空間を持つと
区別がつかない。

# 2. reranker は「読めないもの」を動かしてはならない

cross-encoder は (query, text) の対を採点する。C には採点対象のテキストが無い。
**無いものに点を付けると、ベクトルが正しく置いた順位を壊す。**qb22 がそれである。

**棄権 = 順位を動かさない**、と定義する。
reranker は自分が読める候補 (A/B) の**間だけ**を並べ替え、
C は**元の枠に残す**。読めない文書を動かさない判事、という以上の意味は無い。

## 2.1 実測 — 棄権すると何が変わるか

既存の dump と 3 本の出力に対して、後処理で棄権を模擬した:

| | Recall@10 |
|---|---|
| baseline | 0.7500 |
| 現行 (全件を reranker に通す) | 0.8750 (**+0.125**) |
| **棄権あり** | **0.9167 (+0.1667)** |

**3 モデルとも同じ。**qb22 を取り戻し、他のどの問も落とさない。
天井 (oracle 実測 1.0000 = +0.25) に対して、**半分から 2/3 に上がる。**

**ただしこの数字は暫定である。**C の判定に使った検出器が
「markdown の画像参照を含み、それ以外の本文が 120 字未満」という**その場しのぎ**で、
2,400 候補中 59 件を凍結した。本番の判定は §3 の信号でなければならない。

# 3. 足りないもの — 判断が記録されていない

**C かどうかは本文から復元できない。**qb22 の chunk は

```
# Rendered citation network

Afterlives of Judgment · Keller-Roth correspondence reading set

![img-0.jpeg](img-0.jpeg)
```

で、表題とキャプションを持つ。「テキストが空だから C」では判定できないし、
実際 §2.1 の検出器は閾値を置いた当てずっぽうである。

**判断を持っているのは OCR (Markdownize Adapter) だけ**なので、
そこで記録する必要がある。現状 `local_ocr_markdownize` は
`![](kio://...)` を含む markdown を出すだけで、
**「これは文字に起こせた / これは画像として残した」を出力していない。**

## 3.1 記録する場所

派生インデックス側に置く。**`chunk_hash` に入れてはならない** —
07 §9 の first-instance-wins が凍結するのは identity で、
OCR の判断が変わるたびに identity が動くと、再 OCR が別文書に見える。
`crate::search_projection` や (revert 済みの) `text_words` と同じ扱いにする。

# 4. 決めていないこと

- **C のキャプションを FTS に入れるか。**§1 の表は「C は FTS ✗」としたが、
  qb22 のキャプション `Afterlives of Judgment · Keller-Roth correspondence reading set`
  は**語彙的には有用**である。落とすと固有名詞での再現率を失う。
  「本文は入れないがキャプションは入れる」もありうる。**測れば決まる**
- **棄権を誰が実装するか。**Adapter 側 (07 §5.6 の `candidate_features` に
  C を渡さない) か、呼び出し側 (渡すが結果をマージするときに枠を固定する) か。
  trait は既に不透明な `result_id` しか渡さないので、**呼び出し側が自然**
- **画像しか答えを持たない問がどれだけあるか。**fixture-B 24 問では 1 問 (qb22)。
  この 1 問で設計を決めているので、標本は小さい

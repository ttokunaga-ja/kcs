# 語レーンの効果測定 — 事前登録と結果

`tasks/japanese-word-lane-design.md` で設計し実装した word lane (既定 off) を、
**on にする根拠があるか / 消すべきか** を決めるための測定。

**予測は測定より先に書く。**下の §3 は 1 回も走らせる前に書かれており、
走らせた後で書き換えていない。当たったか外れたかは §4 に足す。

---

# 1. なぜ新しいクエリ集合が要るのか

リポジトリ内の既存ゴールデンクエリ 98 問を数えた結果:

| | |
|---|---|
| length rule (05 §1.3、3 scalar 未満を捨てる) が漢字の内容語を落としているクエリ | **92 / 98 (94%)** |
| 落とされた Han run の総数 | **315** (`資料`×10, `万円`×7, `検索`×6, `廃止`×5) |
| 長さだけで生き残る純粋な文法 run | **109** (`だった`×20, `はいくつか`×6, `はいつか`×5) |
| それでも Recall@10 | golden 50 = **1.000** / crossscope 16 = **1.000** / qhard 8/8 |

**倒錯は 94% のクエリで現に起きているのに、一度も recall を落としていない。**
理由はクエリの長さで、90 問の**最短が 14 文字・中央値 29 文字・12 文字以下は 0 問**。
どれも記述文なので、捨てられた内容語の外側に必ず別の識別語が残っている。

語レーンは短いクエリのために作った。**その場合を測る問題が 1 問もない。**

# 2. 器 — `eval/golden-queries-short.jsonl`

自分の機能に有利な問題を書かないための拘束を先に決めた:

1. **M3-1 anchor の全 24 section に 1 問ずつ。**どれを載せるか選べないので、
   有利な事例だけを拾うことが構造的にできない
2. **12 文字以下。**既存 98 問の最短が 14 文字なので、集合として重ならない
3. **語彙は当該 anchor の `title` / `heading` / `facts` に verbatim で現れるものだけ。**
   機械検査済み (この規則に 2 問違反していたので、走らせる前に直した)
4. **形態素解析器の挙動を見ずに書く。**文書を思い浮かべて打つ言葉を書く
5. **走らせる前に凍結する**

コーパスには一切手を入れていない (crossscope 増補と同じ方針)。
`run_eval.py --golden` が既にあるのでランナー改修も不要。M3-2/M3-3 の
`HISTORY_QUERY_COUNT` 契約は M3-1 のみの実行には当たらない (run_eval.py:1151)。

# 3. 事前予測 (走らせる前に記載)

24 問に length rule を当てた結果 (トリガム側だけの計算、語レーン不関与):

- **pure-short は 0 / 24。**どの問にも 3 文字以上の生存 unit がある
- **内容語が捨てられる問は 18 / 24**
- 生存 unit に `の精度` `の目標` `の定数` `の係数` `の推奨` `の同一性` が並ぶ。
  script run 境界は字種でしか切らないので、**助詞が内容語に溶接されたまま
  1 つの unit になっている。**設計文書が書いた倒錯より一段悪い形

**予測: 語レーン off でも短問集合は天井に近い (Recall@10 >= 0.9)。したがって
レーンによる改善は +0.1 以下、おそらく 0。**

根拠は anchor の語彙的な特異性で、M3-1 の 12 文書はすべて固有名詞
(`Osprey` `Komodo` `RRF` `MMR` `HNSW` `Falcon` `Kestrel` `ベロシティ`
`マネージド`) を持ち、**length rule はカタカナ語も ASCII 語も捨てない。**
内容語の漢字が落ちても、固有名詞が単独で文書を一意に決めてしまう。

対照群は内容語が 1 つも落ちない 6 問 (`ハイブリッドの p99`,
`マイルストーンとベータ`, `スプリントのベロシティ`, `Komodo の QPS`,
`トークンの TTL`, `chunk の同一性`)。ここが動いたら、それは改善ではなく事故。

**この予測が当たった場合、結論はレーンではなく器についてのものになる** —
合成コーパスは anchor が語彙的に目立ちすぎて、どんなクエリを書いても
この問題を測れない。その場合の次の一手は合成コーパスの改良ではなく、
実文書コーパス (`tasks/dogfood-realistic-corpus-investigation.md`) への移行。

**反証条件: off が 0.9 を明確に下回れば、レーンには伸びしろがあり、
差分をそのまま効果として読める。**
